# 智慧芽 MCP 使用教程

日期：2026-05-24

本教程面向第一次使用本地智慧芽 MCP 专利情报工具的人。工具当前接通两个通道：

- 专利搜索：`https://connect.zhihuiya.com/2b0355/logic-mcp`
- 专利查新：`https://connect.zhihuiya.com/bec69d/mcp`

请注意：本工具用于专利情报初筛、查新辅助和风险线索整理，不构成正式法律意见。

## 1. 启动和访问

在项目根目录打开 PowerShell：

```powershell
cd "D:\codex-new\02_projects\_documents_new_projects__20260430\New project 55"
```

首次运行前安装依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

配置本地智慧芽 MCP 密钥：

```powershell
.\scripts\set_zhihuiya_mcp_key.ps1
```

提示输入时，可以粘贴纯 API key，也可以粘贴 marketplace 生成的完整 MCP 链接；脚本会提取其中的 `apikey` 并写入本地 `.env.local`。不要把真实 key 写入 README、Issue、截图或提交记录。

启动服务：

```powershell
.\scripts\run.ps1
```

浏览器访问：

```text
http://127.0.0.1:8787
```

如果页面打不开，先确认 PowerShell 窗口里服务仍在运行，并检查端口是否显示为 `8787`。

## 2. 页面输入项怎么填

### 技术方案输入

这里填写你要查的核心问题。可以是自然语言，也可以是比较完整的技术方案。

适合输入：

- 某个发明人、申请人、公司或高校的专利查询。
- 一段待查新的技术方案。
- 已经写好的专家检索式。

例子：

```text
查询清华大学蔡临宁作为前三发明人的专利
```

```text
一种用于无人机的轻量化复合材料储氢气瓶，采用碳纤维缠绕层、金属内胆和集成泄压阀结构，用于提升储氢安全性和续航能力。
```

### 检索模式

按任务目的选择模式：

- `balanced`：综合检索与排序。适合一般专利查询、申请人/发明人查询、技术主题摸底。
- `novelty`：技术方案查新。适合把一段方案拿来做新颖性和相似专利初筛。
- `infringement`：侵权或 FTO 风险初筛。适合初步观察是否可能靠近他人权利要求。
- `landscape`：技术布局观察。适合看某方向主要申请人、技术分布和代表性专利。
- `raw`：直接发送专家检索式。适合熟悉智慧芽检索语法的用户。

后端会按模式选择通道：`balanced` / `landscape` 默认走专利搜索，`novelty` / `infringement` 默认走专利查新。若专利搜索通道权限不足，后端可能尝试用查新通道兜底。

### 返回条数

填写希望返回的候选数量。常用范围：

- `5`：快速试查，适合确认关键词和通道是否有效。
- `10`：默认推荐，信息量适中。
- `20`：需要更多候选时使用，但结果更需要人工筛选。

返回条数不是越大越好。第一次查建议先用 `10`，根据结果再调整问题或检索式。

### 补充上下文

这里填写额外约束或背景，帮助工具判断相关性。

可填写：

- 重点关注国家或地区，例如“中国专利为主”。
- 申请人范围，例如“优先看高校和科研院所”。
- 技术边界，例如“不考虑纯软件方案”。
- 使用场景，例如“用于项目立项查新，不作为侵权结论”。

例子：

```text
关注中国公开专利；重点看复合材料储氢气瓶、泄压阀、无人机供氢应用；排除普通车载储氢瓶。
```

如果没有特别约束，可以留空。

## 3. 三个典型示例

### 示例 A：发明人/申请人查询

适合问题：想看某个人、某单位、某公司有哪些相关专利。

填写方式：

```text
技术方案输入：查询清华大学蔡临宁作为前三发明人的专利
检索模式：balanced
返回条数：10
补充上下文：优先返回与工程应用、传感、装备相关的专利；如果发明人字段不完整，请在证据中说明。
```

预期结果：

- 任务卡会识别这是发明人查询。
- Top 专利会列出候选专利。
- 证据中应能看到发明人、申请人、标题或摘要等命中依据。
- 如果没有命中，尝试改成“蔡临宁 清华大学 专利”或增加英文/拼音变体。

### 示例 B：技术方案查新

适合问题：手里有一段技术方案，想快速看是否已有相似公开专利。

填写方式：

```text
技术方案输入：一种用于无人机的轻量化复合材料储氢气瓶，采用碳纤维缠绕层、金属内胆和集成泄压阀结构，通过传感器监测压力温度并联动安全泄放，用于提升储氢安全性和续航能力。
检索模式：novelty
返回条数：10
补充上下文：关注气瓶结构、缠绕层、泄压阀、无人机供氢场景；请区分相似点和差异点。
```

预期结果：

- 任务卡会把输入识别为技术方案查新。
- Top 专利列出相似公开专利。
- 相似点会提示哪些结构、用途或技术效果已经出现。
- 差异点会提示你的方案与现有专利可能不同的地方。
- 风险摘要会给出高/中/低等初筛判断或不确定性说明。

### 示例 C：raw 专家检索式

适合问题：你已经会写智慧芽检索式，希望尽量减少自然语言改写。

填写方式：

```text
技术方案输入：TACD:("hydrogen storage tank" OR "pressure vessel") AND TACD:(composite OR carbon fiber) AND TACD:(UAV OR drone)
检索模式：raw
返回条数：10
补充上下文：仅用于专家检索式直查；请保留原始检索意图。
```

也可以在输入开头显式写：

```text
raw: TACD:("hydrogen storage tank" OR "pressure vessel") AND TACD:(composite OR carbon fiber)
```

预期结果：

- 后端会尽量把输入作为检索式发送。
- 如果语法错误或字段不被当前 MCP 工具支持，结果可能为空或返回错误。
- raw 模式更依赖用户自己控制检索语法，适合二次精查。

## 4. 如何看结果

### 任务卡

任务卡是工具对本次输入的结构化理解，通常包括：

- 本次问题属于查询、查新、风险初筛还是布局观察。
- 识别出的核心对象，例如发明人、申请人、关键词、技术主题。
- 本次使用的模式和返回条数。

先看任务卡是否理解正确。如果任务卡理解偏了，优先修改输入问题，而不是急着看专利列表。

### Top 专利

Top 专利是最值得先看的候选结果。重点看：

- 标题是否与问题相关。
- 申请人/发明人是否符合预期。
- 摘要、权利要求或公开文本是否覆盖核心技术特征。
- 排名靠前的原因是否清楚。

Top 专利只是初筛排序，不等于最终结论。重要项目仍需人工复核全文、权利要求和法律状态。

### 相似点/差异点

查新和风险场景下，要重点看：

- 相似点：现有专利已经公开了哪些结构、步骤、用途或效果。
- 差异点：你的方案可能在哪里有区别，例如组合方式、应用场景、参数范围、控制逻辑。
- 不确定性：如果结果缺少权利要求、说明书全文或法律状态，工具应提示证据不足。

写交底书或立项材料时，差异点可以作为后续创新点打磨线索，但不能直接当成授权结论。

### 风险摘要

风险摘要用于快速判断本次结果的专利风险或查新压力。

常见含义：

- 高风险：命中结果与核心结构或用途高度接近，需要重点复核。
- 中风险：存在若干相似公开，需要进一步限定技术特征。
- 低风险：当前结果未发现明显高度相似项，但仍受检索范围和数据完整性限制。
- 不确定：MCP 返回字段不足、结果过少或查询条件过宽，需要重新检索。

### 证据

证据区是最重要的复核入口。优先看：

- 哪些字段支持结论，例如标题、摘要、申请人、发明人、公开文本片段。
- 是否有可追溯的专利号、公开号或链接。
- 证据是否真的对应本次问题，而不是泛泛相似。

如果证据弱，风险摘要再漂亮也要谨慎。

### `trace_id`

`trace_id` 是本地排查编号。遇到异常、结果不稳定或需要复现时，请记录：

- 输入内容。
- 检索模式。
- 返回条数。
- 错误信息或异常表现。
- `trace_id`。

后续排查日志或 Issue 时，`trace_id` 可以帮助定位本次请求。

## 5. 常见错误和处理

### 缺 key

表现：

- 页面提示密钥缺失。
- `/api/health` 显示 `has_api_key` 为 false。

处理：

```powershell
.\scripts\set_zhihuiya_mcp_key.ps1
```

重新输入有效 key 后，再重启服务。

### `auth_failed`

含义：认证失败，通常是 key 错误、过期或复制不完整。

处理：

- 确认没有多复制空格、引号或换行。
- 确认 key 来自正确的智慧芽 marketplace MCP 服务。
- 重新运行 `.\scripts\set_zhihuiya_mcp_key.ps1`。
- 如仍失败，在智慧芽平台重新生成或轮换 key。

### `permission_denied`

含义：当前 key 没有权限访问对应 MCP 服务或工具。

处理：

- 确认账号已开通对应 marketplace 服务。
- 区分两个通道权限：专利搜索 `/2b0355/logic-mcp` 与专利查新 `/bec69d/mcp`。
- 如果 `balanced` 可用但 `novelty` 不可用，可能是查新通道权限不足。
- 如果 `novelty` 可用但 `balanced` 不可用，可能是专利搜索通道权限不足。

### 无结果

可能原因：

- 问题太窄，例如人名、单位名或字段条件过于严格。
- 检索式语法错误。
- 返回条数太少。
- 当前 MCP 工具没有返回可解析字段。

处理：

- 先把返回条数调到 `10` 或 `20`。
- 放宽关键词，例如去掉“前三发明人”等限制。
- 用同义词补充，例如“储氢瓶 / 氢气瓶 / pressure vessel / hydrogen tank”。
- raw 模式下检查字段名、括号和引号。

### 结果不相关

可能原因：

- 输入太泛，例如只写“氢能源”。
- 补充上下文为空，工具无法判断应用边界。
- 检索模式不匹配，例如查新任务用了 raw 或一般查询模式。

处理：

- 在技术方案输入中写清结构、用途、关键部件和技术效果。
- 在补充上下文中写清排除项。
- 技术方案相似性判断优先用 `novelty`。
- 发明人/申请人查询优先用 `balanced`。

## 6. 密钥安全提醒

- 不要在 README、教程、Issue、提交记录、聊天截图或日志中写真实 key。
- 不要上传 `.env.local`、`.env` 或任何包含密钥的配置文件。
- 示例中只能使用 `your_local_key_here` 这类占位符。
- 如果完整带 `apikey` 的 URL 曾经被贴到公开位置，应立即在智慧芽平台轮换 key。
- 共享结果报告时，确认其中没有带密钥的请求地址或调试信息。
