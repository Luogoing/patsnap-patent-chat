# 智慧芽 MCP 项目一期路线图与开源协作草案

## 1. 课题定位

本课题面向“专利服务 + Agent/MCP 工具化”场景，目标是把智慧芽 marketplace 的「智慧芽专利搜索」能力接入为本地可审计的一期工具。当前仓库已有本地专利检索对话原型，一期重点不是继续修补旧 REST 接口，而是切换到智慧芽 MCP 主通道，并沉淀稳定工具边界、服务记录格式和开源协作入口。

一期工具建议聚焦四类任务：

- 需求理解：把用户的自然语言检索需求整理成技术主题、对象、关键词和排除项。
- 检索式生成：输出可审查、可修改的自然语言检索任务或智慧芽专家检索式。
- 检索执行：通过智慧芽 MCP 获取候选专利，并归一化为任务卡、Top 命中、证据和风险摘要。
- 服务留痕：记录检索过程、结论边界、风险和下一步动作。

## 2. 一期 MCP Tool 草案

### `build_task_card`

输入：

- `user_need`：用户原始需求。
- `domain_hint`：可选，技术领域提示。
- `must_include`：可选，必须包含的关键词或分类号。
- `must_exclude`：可选，需要排除的关键词。

输出：

- `task_card`：检索任务卡。
- `query_notes`：任务解释和需要确认的边界。
- `review_points`：需要人工确认的歧义点。

### `search_patents_via_mcp`

输入：

- `query`：自然语言任务或人工确认后的智慧芽检索式。
- `limit`：返回条数，默认小样本。
- `include_count`：是否返回计数。

输出：

- `items`：候选专利摘要。
- `source_query`：实际执行的检索式。
- `warnings`：接口、权限、字段缺失或结果不稳定提示。

### `record_service_case`

输入：

- `case_title`：服务案例标题。
- `need_summary`：需求摘要。
- `query_strategy`：检索策略。
- `result_summary`：结果摘要。
- `risk_notes`：风险和边界。
- `next_actions`：下一步动作。

输出：

- `case_markdown`：可保存到 `02_outputs` 或 Issue 的服务记录 Markdown。

| 阶段 | 目标 | 产出 | 验收口径 |
| --- | --- | --- | --- |
| M1 本地验证 | 跑通 MCP 检索原型 | README、运行命令、样例查询 | Windows PowerShell 可按文档启动 |
| M2 工具拆分 | 明确情报工作流输入输出 | API schema 草案、调用示例 | 每个步骤有清晰入参、出参、错误边界 |

## 5. 开源贡献规则草案

- 优先中文提交问题和案例，英文补充可选。
- 真实客户、项目、密钥、下载链接、截图中的账号信息必须脱敏。
- 禁止提交完整带 `apikey`、`token`、`secret`、`sk` 的 URL 或日志。
- 涉及接口字段、错误码、检索语法时，优先给最小可复现样例。
- 新增功能建议先开 Issue 对齐边界，再提交 PR。
- PR 应拆小：文档、工具 schema、后端实现、前端交互、测试尽量分开。
- 面向 MCP 的新增能力必须说明输入、输出、失败模式和安全限制。

## 6. 密钥与敏感信息安全

必须遵守：

- 不上传 `.env`、`.env.local`、真实 `sk` 或任何私有凭据。
- 不在文档中写完整带密钥 URL，例如不要写 `...?apikey=<真实值>`。
- 示例统一使用占位符，例如 `ZHIHUIYA_MCP_API_KEY=your_local_key_here`。
- 如果密钥已经暴露，应立即轮换，并清理公开 Issue、提交历史、日志和截图。
- 发布前用人工检查加关键词搜索确认没有完整带密钥 URL、真实 token 或私有凭据。

发布前可执行：

```powershell
git grep -n "apikey=\\|Authorization: Bearer\\|ZHIHUIYA_MCP_API_KEY\\|PATSNAP_API_KEY" -- . ":(exclude).env.example"
```

命中结果需要逐条判断：示例占位符可以保留，真实密钥必须删除并轮换。
